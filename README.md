# V&A LightStudio

Одностраничный интернет-каталог авторских деревянных светильников V&A LightStudio.

Проект представляет собой адаптивный статический сайт-каталог с интерактивным каталогом товаров, фильтрацией и сортировкой, карточками товаров, корзиной и формой оформления заказа. Сайт ориентирован на продажу светильников из натурального берёзового шпона с доставкой по Беларуси и в РФ.

## Результат

В результате разработки получен полноценный frontend интернет-магазина без отдельного backend-приложения:

- динамический каталог светильников, загружаемый из Google Sheets через Google Apps Script;
- фильтрация по типу изделия;
- сортировка по цене;
- подробные карточки товаров;
- галерея изображений для каждой модели;
- добавление товаров в корзину;
- изменение количества и удаление товаров;
- сохранение корзины в `localStorage`;
- восстановление корзины после перезагрузки страницы независимо от загрузки каталога;
- автоматический расчёт итоговой стоимости;
- оформление заказа через форму;
- передача заявок в Google Apps Script;
- валидация пользовательских данных на клиенте;
- динамическая логика доставки в зависимости от населённого пункта;
- адаптивная мобильная навигация;
- модальные окна для товаров, корзины и документов;
- клавиатурная навигация и управление фокусом в диалогах;
- поддержка `Escape` для закрытия интерактивных элементов;
- SEO-метаданные и структурированные данные Schema.org;
- PWA/web app manifest;
- GitHub Pages deployment через GitHub Actions;
- изображения переведены в WebP;
- часть статических изображений вынесена во внешнее хранилище и подключается по URL;
- JavaScript-файл закодирован для затруднения прямого чтения исходного кода в браузере;
- локальные шрифты используются без зависимости от внешних font CDN.

## Что было сделано

### 1. Создан полноценный каталог

Каталог реализован без отдельной CMS и собственной backend-базы. Актуальные данные товаров хранятся во внешней таблице Google Sheets и выдаются frontend через Google Apps Script API.

Запись товара в каталоге содержит:

- название;
- подзаголовок;
- цену;
- размеры;
- категорию;
- тип;
- описание;
- основное изображение;
- дополнительные изображения;
- ссылку на дополнительный материал в Instagram.

Каталог формируется динамически через JavaScript, поэтому HTML не содержит отдельные статические карточки товаров. Frontend получает данные из внешнего источника при загрузке страницы.

### 2. Реализована фильтрация и сортировка

Пользователь может:

- посмотреть все модели;
- выбрать потолочные светильники;
- выбрать универсальные модели «потолочный / настольный»;
- отсортировать каталог от дешёвых к дорогим;
- отсортировать каталог от дорогих к дешёвым.

Количество всех моделей выводится динамически.

### 3. Реализованы карточки и модальные окна товаров

Для каждого товара предусмотрена отдельная карточка с основной информацией.

В модальном окне доступны:

- крупное изображение;
- переключение фотографий;
- счётчик изображений;
- название;
- тип;
- размеры;
- цена;
- комплектация;
- добавление в корзину;
- переход к дополнительному материалу в Instagram, если он предусмотрен.

Изображения и данные подставляются динамически на основании выбранного товара.

### 4. Реализована корзина

Корзина работает полностью на стороне клиента, а её состояние сохраняется в `localStorage`.

Поддерживаются:

- добавление товара;
- повторное добавление существующего товара;
- изменение количества;
- удаление позиции;
- отображение количества товаров;
- расчёт общей стоимости;
- отображение состава заказа;
- переход из корзины к оформлению.

Состояние корзины сохраняется в `localStorage`, поэтому товары не исчезают при обычной перезагрузке страницы. При запуске страницы корзина восстанавливается независимо от момента загрузки внешнего каталога, после чего позиции синхронизируются с актуальными данными товаров.

### 5. Реализована форма заказа

Форма содержит:

- имя;
- телефон;
- населённый пункт;
- способ получения;
- комментарий;
- состав выбранного заказа.

Перед отправкой выполняется клиентская валидация.

Проверяются:

- обязательность полей;
- длина имени;
- формат имени;
- формат телефона Беларуси и России;
- населённый пункт;
- способ доставки;
- максимальная длина комментария.

Ошибки отображаются непосредственно возле соответствующих полей и сопровождаются `aria-invalid` / `aria-live` для доступности.

### 6. Реализована логика доставки

В зависимости от указанного населённого пункта динамически изменяются доступные способы получения.

Для Минска доступны варианты, связанные с самовывозом и доставкой по Минску.

Для других населённых пунктов соответствующие минские варианты недоступны.

Это уменьшает вероятность оформления заказа с несовместимым способом доставки.

### 7. Подключена отправка заказов

Frontend отправляет подготовленные данные формы в Google Apps Script.

Передаваемые данные включают:

- контактные данные клиента;
- населённый пункт;
- способ доставки;
- комментарий;
- состав корзины;
- количество товаров;
- цены товаров.

После успешной обработки пользователь получает понятное подтверждение.

При ошибке сети или ответа сервиса интерфейс сообщает о невозможности отправки.

Конкретные служебные URL и конфигурационные значения в README намеренно не публикуются.

### 8. Подключён внешний каталог и локальный кэш

Каталог больше не является статическим набором данных внутри frontend-кода.

Реализована схема:

`Google Sheets → Google Apps Script → JavaScript → каталог`

Для ускорения первоначального отображения используется локальный кэш каталога в `localStorage`:

- сохранённые данные показываются сразу;
- актуальные данные запрашиваются в фоне;
- после успешного ответа кэш обновляется;
- при временной недоступности API используется последний сохранённый каталог.

Это позволяет одновременно изменять каталог без редактирования HTML/JS и сохранять работоспособность интерфейса при временных сетевых ошибках.

### 9. Проведён рефакторинг frontend-логики

В ходе работы была упрощена клиентская логика:

- уменьшена связанность между UI-компонентами;
- обработчики интерактивных элементов унифицированы через `data-action`;
- логика модальных окон приведена к единому подходу;
- обработка корзины централизована;
- фильтрация и сортировка отделены от рендеринга;
- валидация формы разделена по отдельным функциям;
- удалена избыточная логика;
- проверены сценарии закрытия диалогов и взаимодействия с клавиатурой.

Это сделало код проще для сопровождения и уменьшило количество дублирования.

### 10. Улучшена работа модальных окон

Реализованы отдельные сценарии для:

- карточки товара;
- корзины;
- сообщения об успешной отправке;
- свидетельства о государственной регистрации.

Для диалогов предусмотрены:

- ограничение перемещения фокуса внутри открытого диалога;

## Защита клиентского JavaScript

Основной файл `scripts/script.js` в репозитории хранится в закодированном виде. При загрузке страницы браузер декодирует содержимое и выполняет исходную JavaScript-логику.

Это предназначено прежде всего для затруднения прямого просмотра исходника в репозитории и браузере.

Важно: такое кодирование **не является криптографической защитой**. Код, который выполняется в браузере, технически доступен пользователю и может быть восстановлен. Поэтому encoding не следует рассматривать как способ защиты секретов.

### Presentation

- визуальную систему;

### Application logic

JavaScript отвечает за:

- получение данных каталога через Google Apps Script;
- локальный кэш каталога;
- рендеринг товаров;
- фильтрацию;

### Backend integration

Google Apps Script используется в двух интеграционных сценариях:

1. внешний endpoint каталога — получение актуальных товаров из Google Sheets;
2. endpoint заказов — обработка заявок из формы.

Собственного backend-приложения Node.js/PHP/Express в проекте нет.

Отдельный сервер Node.js/PHP/Express для frontend не требуется.

## Безопасность

В проекте не используется хранение паролей или пользовательских токенов.

При работе с пользовательским вводом:

- значения проходят валидацию;
- пользовательские данные не вставляются в DOM как произвольный HTML;
- ссылки на внешние ресурсы открываются с `noopener noreferrer`, где это необходимо;
- служебные значения интеграции не документируются в открытом README.

Важно: frontend-секреты нельзя считать настоящими секретами. Любое значение, присутствующее в JavaScript браузера, потенциально доступно пользователю. Поэтому критичные секреты не должны находиться во frontend-коде.

## Ограничения

Проект является frontend-приложением, поэтому:

- каталог хранится во внешней Google Sheets и загружается через Apps Script;
- корзина хранится в браузере;
- авторизации пользователей нет;
- отдельной серверной базы данных нет;
- административной панели нет;
- управление товарами выполняется через Google Sheets без необходимости редактировать HTML/JS;
- автоматическая синхронизация остатков отсутствует.

Google Apps Script используется как интеграционный слой для каталога и обработки заявок. Он не превращает frontend в полноценную серверную CMS.

## Локальный запуск

Проект не требует установки зависимостей.

Можно открыть `index.html` локально, однако для корректной работы некоторых браузерных сценариев рекомендуется запускать проект через локальный HTTP-сервер.

Например, через VS Code Live Server или любой другой простой static server.

## Деплой

Основной способ публикации — GitHub Pages через GitHub Actions.

После изменения проекта:

1. изменения отправляются в репозиторий;
2. GitHub Actions запускает workflow;
3. статические файлы публикуются;
4. сайт обновляется без отдельной серверной сборки.
